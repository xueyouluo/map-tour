# 使用报表、事件与错误排查

管理员进入 `/admin` → **使用报表**。可选择今天、最近 7 / 30 / 90 天，按操作、浏览器、完整用户 ID、结果筛选。支持操作明细分页、失败原因聚合、每日导出趋势、浏览器分布、成功耗时中位数 / P95。详情含构建版本、场景/行程/尝试 ID、错误原因链、浏览器与渲染状态，便于从用户反馈定位。

## 采集范围与结果定义

| 操作 | 来源 | 开始 / 最终结果 | 成功含义 |
| --- | --- | --- | --- |
| `auth.register` / `auth.login` | 服务端 | 开始、成功、失败、拦截 | 账号创建或会话建立成功；失败只记录固定原因分类，凭据、用户名与 IP 不入事件库 |
| `itinerary.save` | 服务端 | 开始、成功、失败、拦截 | 编辑保存已写入行程库；重复保存按独立请求计数 |
| `share.publish` | 服务端 | 开始、成功、失败、拦截 | 用户点击分享并成功保存为 shared，包含重复生成链接 |
| `share.open` | 服务端 | 开始、成功、失败 | 分享页数据加载成功，含匿名访问与作者自访；普通历史读取和 HEAD 不计；不表示地图已就绪，不是独立访客 UV |
| `share.copy` | 浏览器 | 开始、成功、失败、中断 | 链接已写入剪贴板，不表示接收方已打开 |
| `quota.blocked` | 前端或服务端 | 拦截 | 因额度不足阻止解析/另存；前端挡住后不发业务请求，服务端最终校验也独立记录 |
| `itinerary.parse` | 服务端 | 开始、成功、失败 | 解析结果已保存到行程库，包含文字/图片输入类别 |
| `video.scene` | 服务端 | 开始、成功、失败 | 场景入口已创建（可能复用缓存），不表示地图或 MP4 已加载 |
| `video.preview` | 浏览器 | 开始、成功、失败、中断 | iframe 场景已 `sampleReady`，播放器可用 |
| `video.export` | 浏览器 | 开始、成功、失败、取消、中断 | 1080×1920 MP4 已生成并通过解码验证，记录时长/字节数/音乐类别/存储状态 |
| `video.background` | 服务端 | 开始、成功、失败、取消、中断 | 后台成片验证通过；新任务开始计时含排队时间，重复提交复用任务不增加尝试 |
| `video.fallback` | 浏览器 | 开始、成功、失败 | 转后台请求被接受，不表示后台制作完成 |
| `video.download` | 浏览器 | 点击 | 用户点击下载按钮；无法确认已保存到磁盘，可重复点击 |
| `video.storage` | 浏览器 | 失败 | 本机视频持久化失败，但已生成的内存视频仍算导出成功 |
| `video.request` | 浏览器 | 失败 | 视频接口异常，保留旧客户端上报兼容性 |
| `runtime.error` / `runtime.rejection` | 浏览器 | 失败 | 页面或已加载场景的未捕获异常 |
| `server.error` | 服务端 | 失败 | 其他 API 意外异常、地图代理失败；已经有独立流程结果的错误不重复入报表 |

服务端流程从通过身份/额度/上传中间件后开始；被中间件直接拒绝的请求不纳入解析尝试。后台队列接受前失败由调用方界面提示，转后台请求失败另有记录。预览成功后发生的运行异常单独记录，不改写已成功的预览加载结果。

每次操作有独立 `attemptId`。开始、30 秒心跳和最终结果合并为一次尝试，重复上报按事件 ID 和操作/尝试/状态持久去重。取消、页面离开和后台服务重启各有状态；两分钟没有新进度且没有最终结果时显示“结果未确认”，不武断计为失败。后台排队也持续发送心跳。迟到的开始/心跳不覆盖最终结果，迟到的成功会更新未确认/中断。

- 成功率 = 成功 ÷（成功 + 失败）；没有已知结果显示 `—`，取消、中断、业务拦截、进行中和未确认单列。账号限流、关闭注册和额度不足均不作为系统失败。
- 时长统计只计成功操作；后台耗时含排队。
- 时区固定 `Asia/Shanghai`，按服务端首次接收到该次操作事件的日期归档。跨日期的操作整体归入开始日期；离线补报可能推迟日期。日期、浏览器、用户和结果筛选共同影响报表全部统计。
- “有记录的用户”是筛选范围内事件涉及的去重登录用户，不等于全站访问 UV。场景入口、预览、导出均可多次重复，各步骤计数不等同于用户转化漏斗。
- 缺少开始事件的终态也会保留并标明采集缺口；历史未采集的本机成功无法补回，旧场景 job 的 `completed` 不能用于推算导出成功。

## 存储、权限与可靠性

客户端通过同源 `POST /api/diagnostics/events` 上报，需要有效登录。用户身份由服务端会话确定，拒绝客户端伪造服务端操作。事件存入主 SQLite 的 `analytics_events`，采集启用时间存于 `analytics_meta`。保留 90 天，写入/查询时清理超期事件；服务重启不丢失历史。管理员接口 `GET /api/admin/reports` 使用与用户管理相同的管理员权限校验，匿名 401、普通用户 403，响应不缓存。

浏览器待报队列按登录用户隔离，最多 60 条，超限优先丢弃心跳；尝试写入当前标签页的 sessionStorage，24 小时内刷新可恢复。恢复网络、后续报告和离页触发发送；网络错误/5xx 指数退避 5–60 秒，429 遵循 Retry-After。401/403 清空当前待报队列，切换账户不串报。终止进程、清理存储、持续断网、旧页面、浏览器崩溃时仍可能丢失事件，因此结果未确认单独展示。

失败事件每个账户每分钟最多 30 条，其他事件每分钟 120 条，请求不超过 16 KiB。上报失败不打断业务，也不递归上报自身错误。本机持久化失败单独记录，避免成片成功被误算失败。

只收集白名单字段，不发送密码、令牌、用户名、行程正文、坐标、截图、视频或自选音乐。匿名分享访问、认证失败不推测用户 ID，也不创建跨页面访客指纹。URL 去除凭证、查询参数和片段，常见密钥字段脱敏。错误保留 `name`、`message`、`stack` 和最多三层原因链，兼容跨 iframe 异常。服务端再次校验、限长和脱敏。`buildId` 与资源文件哈希用于区分旧页面；发布时可为前后端设置相同 `MAP_TOUR_BUILD_ID`。

## 日志查询

生产 `map-tour.service` 标准输出/错误进入 journald。浏览器失败为 `client.error`，其他生命周期结果为 `client.event`；心跳仅入库。服务端错误保留 `server.error`，存储失败为 `analytics.persistence_error`。journald 保留时长取决于服务器配置。

```bash
# 最近一小时的浏览器错误（服务器没有 rg 时用 grep）
journalctl -u map-tour --since '1 hour ago' -o cat | grep '"event":"client.error"'

# 按场景检索错误及成功事件
journalctl -u map-tour --since today -o cat | jq -R 'fromjson? | select(.sceneId == "SCENE_ID")'

# 服务端错误
journalctl -u map-tour --since today -o cat | grep '"event":"server.error"'
```

先按反馈时间、用户 ID 或场景定位，再看失败阶段、`error.cause`、具体帧号、素材队列状态和浏览器版本。新增采集需同时发布前后端，部署后打开的新页面才有完整生命周期数据。服务端构建标识读取 MAP_TOUR_BUILD_ID 或生产 RELEASE 文件。

分享页使用 `?view=share` 的同源数据请求计数；机器人、作者自访、登录后重新读取都可能计入。客户端等会话确认后再读取，避免首次打开时因身份尚未确定重复采集。身份在认证成功后才确定，服务端尝试按服务器生成的 ID 合并；客户端仍按用户隔离，避免跨账号串联。安全中间件直接拒绝的跨站、非 JSON 等请求不进入业务尝试统计。

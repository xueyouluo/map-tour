# 旅程视频

行程页面的“生成旅程视频”把完整行程制作成连续地图视频。每天的足迹保留在同一张地图上，小车或步行人物沿路线前进，镜头自动跟随、缩放。输出为 1080×1920、30 fps、H.264 MP4，有配乐时包含 AAC 音轨。

人物与载具采用清晰易辨的地图旅行小模型：黄色越野车、户外背包旅行者、公交、地铁、城际列车、轮渡和飞机。紧凑的载具轮廓、鲜明配色、四档柔和明暗和细轮廓线让模型在地图上保持辨识度，玻璃与轮毂保留适度高光；实时预览与导出共用模型和材质。人物配备鸭舌帽、背包和卷垫，通过关节长度计算支撑脚落地和摆动脚抬起，躯干绕腰部轻微摆动；前轮随转向偏转，轮渡有轻微摇摆与尾流，飞机随转弯轻微倾斜。

列车与地铁的两节车厢分别沿当前路线取样位置与朝向，连接处的风挡随车厢转弯伸缩；起终点仅延伸模型所需的切线，不新增路线。地名、交通及活动标签在影片安全区域内避开模型和已放置的标签，引线从模型边缘外开始绘制，减少到站文字遮住车顶的情况。

路线位置与轨迹共同使用缓起缓停进度，保持原有到站时间。模型朝向采用路段内的角度平滑，不随镜头摇摆；任意拖动和逐帧导出使用确定性的姿态。固定细节按材质合并，保留关节和车轮的独立变换。已准备的场景在权限与有效期校验后读取当前 `film.js` 和 `vehicles.js`，避免旧模型模块与新动画接口不兼容；已导出的 MP4 保留原样，需要重新导出才能体现新画面。

## 用户流程

1. 导入行程，等待地点匹配、路线规划结束，或打开已有行程。
2. 打开视频窗口，选择自动时长或 30 / 60 / 90 秒。不足以容纳路线的时长会禁用。
3. 配乐可以选择内置曲库、自己的音乐或无配乐。内置曲库有五种风格各 A/B 两版，共 10 首，提供开头 20 秒试听；选择会在本机记住，切换工作区或开始生成会停止试听。本地音乐限制为 25 MB，不能短于视频；浏览器读取和解码，手动转后台时服务端另行检查实际音频内容。
4. 点击“预览我的旅程”。支持 H.264 视频编码以及所需 AAC 编码的浏览器，先由浏览器直接下载地图影像与高程、准备配乐，随后在页面内播放真正的 3D 场景，可播放、暂停和拖动进度。
5. 点击“导出 MP4 视频”，通过 WebCodecs 在本机逐帧渲染、编码和封装，不需要把视频上传给服务器。完成后可播放、下载。
6. 浏览器不支持所需编码、本机渲染/编码出错或长时间无进展时，显示具体阶段与失败原因，保留预览并提供“重试本机导出”。只有用户选择“直接使用后台制作”或“改用后台制作”才创建后台视频；仍使用原行程快照、时长和配乐。

本机导出时需要保持页面打开，但允许切换标签页。进入后台不再主动取消导出，浏览器可能降低速度；关闭标签页、退出浏览器或系统终止页面仍会中断任务。导出期间会提供离页提醒。后台制作可关闭窗口或刷新，稍后回来查看。

地点未匹配时不会编造坐标。缺少规划数据的衔接保留为示意线，提交前与成片中都有提示。只在页面选择某一天，不会裁掉视频中的其他天。镜头按路线长短分配时间，当前没有自动识别音乐节拍。

## 实现与运行环境

- `src/browserVideo.ts`：编码能力检测，Mediabunny + WebCodecs 的 H.264/AAC 编码与 MP4 封装，逐帧时间戳、输出格式检查、本地 IndexedDB 存储。编码模块按需加载，不进入页面首屏主包。
- `src/VideoExport.tsx`：配置、素材准备、实时场景、浏览器导出、取消、失败重试、手动后台交接、两类历史记录。
- `tools/video-preview/browser/film.js`：浏览器和后台复用的 Three.js 场景；`seekAsync` 等待当前镜头高清纹理就绪后输出确定帧。嵌入页面时降低纹理驻留量，可见补片不会被移除。
- `server/videoJobs.ts`：`scene` 只同步保存轻量场景计划，不占后台队列；完整后台视频使用单 worker 持久队列，由 Chrome + FFmpeg 制作。
- 浏览器预览需要 `AMAP_JSAPI_KEY`、`AMAP_SECURITY_JS_CODE` 和认证代理。只有手动后台制作需要服务器 Chrome/Chromium、`ffmpeg`、`ffprobe`、`curl`。
- 浏览器导出要求 HTTPS 或 localhost 安全上下文，运行时检测实际编码格式。移动设备的显存、内存和速度存在差异，执行失败会显示原因，由用户决定是否重试或手动转后台。
- 卫星图源于高德 JSAPI，真实高程来自公开 Mapzen Terrarium；影像与高程由浏览器直连上游，地图安全码保留在服务端。没有 AI 视频生成、Suno API 或额外音乐生成服务。

内置曲库由用户提供的 Suno MP3 导入，归一化至约 -16 LUFS，真峰值目标 -2 dBTP，保留完整音轨并另制 20 秒试听。缺少曲库时保留原版 120 BPM 程序合成器乐。内置与上传音乐均使用连续片段，不改变速度，带淡入淡出；浏览器与后台按相同的音量、裁剪和淡入淡出参数分别处理音频。浏览器 AAC 编码可能包含几十毫秒的编码延迟。

运行 `npm run music:import -- --source /绝对路径/合集目录` 可导入本次编号 01–10 的五组 A/B 文件。导入使用两遍响度归一化、解码校验、源文件和成品 SHA-256、不可变音频文件名及原子目录清单更新；不会修改源文件。曲库位于 `assets/music/`（可用 `VIDEO_MUSIC_DIR` 指向其他目录），完整音轨不通过通用静态文件服务公开，提供曲库元信息、试听，以及当前用户场景专属的原始 MP3 端点；可配置外部 CDN 直接下载。首次接入需重启 API。曲库文件独立于下载来源文件夹。

曲目为“晴天出发”“湖边散步”“城市明信片”“山野小路”“江南来信”，每种两个版本；A/B 标签对应合集文件顺序，未按主观喜好淘汰版本。生成时的授权记录应随来源另存，导入工具不会替用户推定授权。

## 保存、恢复与隔离

- 浏览器成片保存在当前网站的 IndexedDB，保留最近 3 条，可刷新恢复。空间不足时仍能下载，但会提示立即保存。浏览器清理网站数据、隐私模式退出等可能清除成片，因此建议下载。
- 浏览器存储与后台 Cookie 是两种独立的恢复方式；本机成片不会自动上传到服务端。删除本机记录会释放其 Blob。
- 后台任务保存在 `VIDEO_EXPORT_DIR/jobs.sqlite`，以独立 UUID 目录保存不可变行程快照，不改原行程数据库。
- 浏览器素材准备需要保持页面打开；刷新后可从保存的场景计划恢复，并复用本机影像缓存。相同快照、参数、音乐和场景代码版本复用未过期计划。
- 后台成片、场景计划和上传音乐保留 7 天，活动任务受保护。后台队列全局最多 20 个未完成任务，每个浏览器最多 2 个，串行执行；浏览器场景计划无需排队。
- 后台取消、重试、删除、进程租约、重启恢复与资产锁继续有效；未知或活跃的其他任务锁不会被接管。
- 任务、场景、上传音乐和媒体路由绑定 HttpOnly、SameSite Cookie；其他浏览器即使知道 UUID 也无法读取。场景路由仅开放播放器、计划、地形、影像和配乐的明确文件白名单，不提供输入快照、日志、manifest 或任意文件路径。
- 场景页面只能由同源页面嵌入。视频播放支持 HTTP Range，私有响应使用 `Cache-Control: private, no-store`；地图 JPG/PNG 使用 `private, no-cache`，每次复用前仍经过权限校验，匹配 ETag 后返回 304。

`data/video-exports/`、`outputs/`、`assets/music/` 已忽略，不要提交任务数据库、音乐、缓存和生成文件。本地部署或迁移时需要单独保留曲库文件与 `catalog.json`。

## API

所有路径位于 `/api/video`，任务/素材使用当前浏览器 Cookie。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/capabilities` | 地图准备与后台制作运行时是否可用 |
| GET | `/music` | 内置曲库元信息，不含文件路径或来源文件信息 |
| GET | `/music/:id/preview` | 内置配乐的 20 秒 MP3 试听，支持 Range |
| POST | `/scenes` | `{ itinerary, options }`，准备浏览器场景 |
| POST | `/jobs` | `{ itinerary, options }`，直接后台制作 |
| GET | `/jobs?itineraryId=ID` | 当前浏览器的行程任务 |
| GET | `/jobs/:id` | 状态、进度和完成后的 URL |
| GET | `/jobs/:id/scene/*` | 已完成私有场景的白名单文件 |
| POST | `/jobs/:id/fallback` | 从原快照和选项创建完整后台视频 |
| POST | `/jobs/:id/cancel` | 取消排队/运行任务 |
| POST | `/jobs/:id/retry` | 保持任务种类，新建重试 |
| DELETE | `/jobs/:id` | 删除终态任务及文件 |
| POST | `/uploads` | 上传 `music` 音频文件 |
| GET | `/jobs/:id/video` | 播放后台 MP4 |
| GET | `/jobs/:id/download` | 下载后台 MP4 |
| GET | `/jobs/:id/cover` | 后台成片封面 |

任务状态为 `queued`、`running`、`cancelling`、`completed`、`failed`、`cancelled`。`kind: scene` 的完成表示素材经过检查且已准备好，不代表视频已生成；仅返回 `sceneUrl`。完整视频只有子进程正常退出且解码、播放验证通过，才发布视频 URL。

内置配乐选项为 `{ music: 'library', trackId: '曲库返回的ID' }`。任务在创建时验证文件校验和与时长，选择及曲名会保留到浏览器导出和后台兜底。`upbeat`、`upload`、`none` 旧选项继续兼容。

## 验证与上线边界

运行 `npm run test`、`npm run build`。验收需要真实生成浏览器视频，验证默认/上传音乐/无配乐、取消、刷新恢复、编码故障和不支持设备的后台兜底、素材白名单与跨浏览器隔离，并对下载 MP4 完整解码、检查关键帧。页面检查覆盖桌面、手机竖屏/横屏和空行程导入。

生产代理应允许 25 MB 上传（例如 `client_max_body_size 32m`），运行账户需要浏览器、字体、编码工具、数据目录和足够磁盘。当前只支持单 worker，多个 API 进程不能共用同一任务目录。服务器部署与运行配置见 [服务器部署](DEPLOYMENT.md)；未对真实 iPhone/Android 设备做验收。

## 旅行电影工作台

当前行程页默认进入电影工作台：深蓝灰背景、冰蓝选中态、暖橙导出按钮。左侧保留可编辑的逐日行程，底部章节条与日程筛选、真实预览跳转联动，点击已匹配地点也可跳到相应镜头；地图作为独立工作区保留。已导出视频可以使用播放器时间轴浏览，章节条继续控制当前行程的日期筛选。

工作台围绕“确认路线 → 预览旅程 → 导出分享”显示当前阶段。顶栏主操作跟随真实状态变化：有未匹配地点时直接打开第一个地点编辑，路线就绪后生成预览，加载完成后导出，成片后下载；不会在无法预览时无反馈地执行。首次预览默认采用自动时长与推荐配乐，时长和曲库按需展开，待确认地点放在配置之前。调整设置时保留原预览，可以应用后重新预览，也可以取消返回。

侧栏保留地点、时间、交通和备注，地址与原文依据合并到“地点详情与依据”，展开不会触发影片跳转。章节使用每日主题，分享入口统一保留在顶栏，避免与下一步操作竞争。新建行程与侧栏导入使用同一个编辑入口，未完成的文字按账户暂存在当前标签页，刷新或关闭编辑弹窗后可恢复；保存行程成功后清除该草稿，解析或保存失败时继续保留。

自己的行程可从地点卡片的“调整地点”按钮上移或下移一站，顺序变更先在侧栏暂存，同一天内可连续调整。用餐和住宿选择与排序一起应用，点击“更新路线”保存后才重算相邻衔接；未改变的路段保留原路径与交通结果。回到原顺序会自动清除排序草稿，也可点击“撤销”整体返回。保存失败保留修改供重试，待应用期间暂停分享与导出，并明确提示影片仍显示原路线。电影工作区为更新操作保留底部空间，不覆盖播放控件；手机展开行程时在详情内提供相同操作。

视频配置、实时预览、任务进度和下载现在直接嵌入页面，不再需要先打开弹窗。顶栏“导出视频”在尚无预览时准备当前行程预览，预览就绪后开始本机导出，已有成片时下载视频。本机编码期间暂时禁用工作区与章节切换。地图仍保持挂载和有效容器尺寸，切换回来时重新适配视野。

播放器外同步显示当前日期、行进路段或到站地点，时间轴使用分:秒并支持键盘定位结尾。自然播完停留在旅程回顾，点击重播从头开始；切换地图或打开其他工作区时暂停隐藏的预览与配乐。地图准备阶段显示不定进度，不把场景入口已生成当作素材已加载完成。旧版本的本机成片仍保留在历史中，但不会自动取代当前风格的预览。

影片路线按当前路段、同一天的足迹、早先日期逐级降低线宽与透明度，切换时平滑过渡；结尾回顾重新显示所有日期的完整路线。当前路段始终绘制在历史足迹之上，路线坐标、虚实线含义和按天分色保持原计划。视觉状态由影片时间计算，倒退跳转、实时播放与逐帧导出一致。

虚线间距随镜头距离调整，远景仍保留可读的间隙；预览线宽按绘制分辨率缩放，保持与 1080P 成片相同的视觉比例。交通说明过长时截断在信息卡内，完整原文仍可在行程详情查看。

手机竖屏保持中央影片、底部章节与可展开行程，配置区可以滚动查看；横屏采用双栏。空行程始终显示导入表单。地图素材和原始路线不会因主题切换而变色或重写，原有按天分色仍用于辨认各天足迹。

## 修正地点后继续生成

未匹配坐标的主路线地点会在视频设置中显示为可点击按钮。点击地点可直接打开位置编辑，按省份、城市和可选区县搜索，核对候选名称与地址，再点击“使用此地点”。行程列表中的每个地点也提供“修改地点 / 确认位置”。轮渡请选择实际码头，二选一车站请选择实际出发站。

## 实时预览性能

实时预览使用 540×960 的绘制缓冲和最高 30 FPS，播放与拖动时间轴不会等待高清图；高清图在后台按距离排序，最多同时加载两张，20 秒超时后释放下载槽，失败后退避重试。缺少高清图时保留完整底图与路线，避免停在某一帧。已完成的路线不再每帧重复上传几何缓冲。

预览专用地图图像最大宽度为 1024 像素，基础地图和细节图都复用原任务中的影像生成。后端最多同时执行一次轻量转换，写临时文件后原子发布，不重新请求高德；派生图随任务清理。所有请求先验证原素材的所有者、过期时间与路径白名单，浏览器复用缓存仍需权限校验。独立 CLI 预览没有派生图服务时，基础地图兼容回退到原图。

本机导出前恢复 1080×1920 与完整阴影质量，加载原始基础地图，并逐帧等待所需原始高清图；成功、取消或失败后都恢复轻量预览，不会把低分辨率预览放大作为高清成片。每个导出帧只绘制一次。后台渲染继续使用完整尺寸，素材准备 CLI 会复制播放器和加载模块。

本机配乐下载按收到的数据更新进度，切换标签页后继续编码并适当放宽无进展超时。主动取消会停止本机输出，真实失败会显示阶段和提示，保留预览供重试。成片检查直接解析 MP4，验证尺寸、时长、H.264/AAC 轨道，并通过 WebCodecs 解码首段、末段画面与配乐，不依赖后台标签页可能暂停的 HTMLVideoElement 事件。最近一次失败摘要保留在该标签页的 sessionStorage，同时向服务端上报诊断事件，见 [错误日志](DIAGNOSTICS.md)。

浏览器直连高德时，细节图按单个共享地图串行采集，外层等待上限为 60 秒，覆盖内部单次 25 秒加载及在途预览采集；排队中的细节图取得采集槽后才开始计时。导出前跳过尚未开始的预览采集，再准备完整底图。每张细节图加载完成会更新进度，避免同一帧等待多张素材时被误判为无响应。iframe 中抛出的错误按 `name` / `message` 读取，避免因不同窗口的 `Error` 类型而丢失具体原因。

私有场景的播放器模块在通过所有者和过期检查后使用当前版本，因此旧预览刷新即可得到播放修复，无需重新解析或重新准备地图。计划、地形、路线、配乐与图片仍读取原任务的不可变快照。`followDiagnostics.playback()` 提供实际绘制数、尺寸及加载队列状态，便于定位设备与网络问题。

手动选择会保留原地点 ID、顺序、时间和原文备注，并记录为手动匹配；不会自动重新匹配覆盖。只使相邻路线失效，跨天衔接也会更新，其余路线复用。修改自己的行程不增加创建额度；修改他人的分享行程需要明确另存为自己的行程，会占用一个额度。候选搜索有省市区约束，搜索失败或没有结果时不编造坐标。

## 浏览器直接准备素材（低带宽服务器）

- `/api/video/scenes` 同步生成并保存路线计划与场景入口，不启动 Chromium、下载高程或采集卫星影像，也不占后台渲染队列。
- 新旧预览统一使用当前浏览器素材模块。浏览器通过高德 JSAPI 的卫星图层直接下载影像，以 `WebGLParams.preserveDrawingBuffer` 保留像素，裁剪原生整数缩放级别的地图图层到纹理；SDK 的安全认证代理仍留在服务端。
- 高程直接从公开 Terrarium 数据源下载，在浏览器按 GCJ02/WGS84 显示对齐并双线性采样。浏览器采用比地图低两级的高程，减少瓦片数；影像清晰度不受影响。失败显示原因，不自动下载服务器截图或提交后台。
- 卫星图与高程只缓存在当前浏览器的 Cache Storage，最多约 160 MiB，七天过期、按写入顺序淘汰。不存行程、账户或密钥；存储不可用时可继续预览。
- 自选配乐保存在浏览器 IndexedDB，七天清理；只有手动选择后台制作才上传。刷新后仍可在同一浏览器使用；清理浏览器数据后需重新选择。
- 内置曲库直接读取原始 MP3，在浏览器裁剪至视频时长并做 -2 dB、30 ms 淡入与 1 s 淡出，不再为每个浏览器场景生成/下载 PCM WAV。原版轻快配乐在本机合成。
- 未配置外部存储时，曲库 MP3 仍通过有所有者校验和 Range 支持的 `/api/video/jobs/:id/audio` 下载。可将 `assets/music/` 中同名哈希 MP3 复制到对象存储/CDN，配置 `VIDEO_MUSIC_CDN_URL=https://cdn.example.com/map-tour/music/` 并启用该网站的 CORS GET/HEAD。这样试听和完整音频直接从 CDN 下载；只配置 URL 不会自动上传文件，也不会创建外部服务。
- Three.js 运行时代码使用含固定版本的地址并设置一年 immutable 缓存；不含用户数据。服务端仍提供登录、行程、AI 解析、少量地图认证代理和可选的手动后台制作。
- 发布必须同时包含 Vite 的 `dist/.vite/manifest.json`、浏览器素材 entry/chunks 与服务端代码；iframe 通过 manifest 解析当前模块地址，避免脚本版本不匹配。旧准备任务无需重新生成地图素材。

## 浏览器与服务端的职责

默认流程优先消耗用户设备的算力和上行网络，而非应用服务器的带宽：

| 工作 | 执行位置 |
| --- | --- |
| 截图转码压缩 | 浏览器；保持原始像素尺寸，JPEG 质量 0.94，仅在至少节省 10% 时采用；小图、超大图或不支持的格式保留原件 |
| 行程理解、截图识别、交通语义推断 | 服务端调用模型；只上传文字或处理后的截图，不在前端暴露模型密钥 |
| 登录、额度、行程和场景计划持久化 | 服务端；保存结构化信息 |
| 地点搜索与路线规划 | 浏览器发起，高德认证代理留在服务端；复用已有未变路线 |
| 卫星影像、高程下载与拼接 | 浏览器直连地图/高程服务并缓存 |
| 音乐解码、裁剪、淡入淡出与 AAC 编码 | 浏览器；自选文件保留本机 |
| 视频渲染、H.264 编码、MP4 封装、检查与下载 | 浏览器；成片不上传 |
| 完整后台渲染与自选音乐上传 | 仅用户手动选择后台制作时执行 |

内置配乐预览使用的完整 MP3 会复用于本机导出；以 SHA-256 在浏览器缓存七天，总量最多约 48 MiB，后续场景使用同一曲目时也无需重复下载音频。每次读缓存前仍向 `/api/video/jobs/:id/audio-source` 发起轻量权限/过期检查，不缓存自选音乐或服务端路径。首次下载由浏览器检查文件哈希，网络中断、校验失败不写缓存；缓存不可用时继续下载播放。源信息可直接指向配置好的音乐 CDN，未配置 CDN 的首次音频请求仍走应用服务器。服务端复用同一文件版本的校验结果，文件元数据变化或替换后重新校验，避免每次请求都读取整个 MP3。

服务端继续提供应用 JS/CSS、受保护的音乐文件及少量接口响应，因此这不是“零服务器流量”。减少首次内置配乐流量需实际上传曲库至对象存储/CDN 并配置地址；不把密钥移至浏览器来绕过认证代理。

## 服务器共享地图缓存

`VIDEO_CACHE_DIR`（未设置时为 `VIDEO_EXPORT_DIR/cache`）中的公共卫星影像和地形瓦片使用独立缓存策略：

- 默认容量上限 **512 MiB**，默认 **7 天未使用**过期；通过 `.env` 的 `VIDEO_CACHE_MAX_MB`（16–4096 MiB）和 `VIDEO_CACHE_TTL_DAYS`（1–90 天）设置，服务端修改后重启生效。无效值使用默认值，不会意外清空缓存。独立视频 CLI 也读取同样配置。
- 服务启动、每小时、后台任务结束时检查。素材读取阶段完成后也检查容量。先移除过期条目，再按最近使用时间淘汰最旧条目，图片和完成记录一起计入容量；命中缓存时更新最近使用时间。
- 只识别 `dem/数字-数字-数字.png` 与 `satellite/64位哈希.jpg`，并要求存在格式正确、包含 SHA256 和对应公共地图来源的完成记录 `.json`。任务目录、场景计划、成片、上传音乐、行程/账号数据库和浏览器缓存不属于清理范围。
- 缓存读取、校验、解码及复制阶段持有跨进程读取租约；登记租约与删除共享同一 SQLite 事务锁，避免“检查后、读取前被删除”的竞争。有读者时延后清理，容量可能暂时超过上限，读取结束后再收敛。主服务也会在有排队或运行任务时延后周期清理。
- 协调信息保存在缓存目录的 `.map-tour-cache.sqlite`，与用户数据库分开。进程退出后 SQLite 的互斥锁自动释放，已退出读者的租约不再阻塞清理；Linux 还校验进程启动标识，避免 PID 重用。
- 遇到其他写入锁、未知协调文件、未完成条目、无法确认归属的文件或符号链接时保留它们，不接管未结束事务。日志会记录跳过或错误；这类受保护内容不以容量目标为由强删。
- 每个任务使用已复制到自身目录的地图素材，不依赖共享缓存一直存在，因此移除共享缓存不改变已生成的预览或视频。需要时可重新下载公共地图素材。

清理日志事件为 `video.cache.cleanup`，包括删除条目数、释放字节数、剩余已识别缓存字节数和跳过原因；独立素材进程的维护失败记录 `video.cache.cleanup_error`，主服务维护失败进入 `server.error`。例如：

```bash
journalctl -u map-tour --since today -o cat | grep 'video.cache.cleanup'
```

不要手动删除未知锁或批量清空 `data/video-exports`。定时器随现有服务运行，无需新增 cron。

管理员「使用报表」中的「服务器地图缓存」展示全站实时文件占用、可管理缓存与其他文件/协调记录的拆分、容量上限、过期规则、活跃读取和写入锁，以及最近 50 次检查的时间、结果、删除条目与释放空间。全站缓存不受操作报表筛选影响；读取只查询，不触发清理或更新缓存最近使用时间。清理历史保存在独立缓存协调库中，跨主服务/素材子进程共享，重启保留，启用前记录不补算。任务占用、读者/写入锁导致的延后和失败单独显示；上限适用于识别出的公共地图缓存，其他文件与协调库不强制清理。
